# 账号与个人空间

## 账号角色与可见范围

访客无需账号即可阅读公开的地图、食谱、菜品、店铺、Wiki 和公告。保留的普通用户账号可以管理自己的账号、私密收藏夹和工单；学生通过社盟账号登录后获得学生角色，可以参与平台内容共建。管理员负责社区管理，运营者拥有更高的账号和运营权限。页面只展示当前账号有权执行的入口，不能通过直接打开链接越过权限限制。

用户主页和公开内容显示已经生效的资料。学生姓名由社盟同步，账号密码登录账号的昵称以及各类账号的头像、展示 ID 和签名按资料审核结果展示；申请结果和拒绝理由在申请列表与消息箱中同时保留。

## 登录方式与账号来源

登录页面显示“通过社盟账号登录”和“使用账号密码登录”两个选项。“通过社盟账号登录”面向普通学生，进入苏州中学社团管理系统的 SSO 单点登录流程；选择“使用账号密码登录”进入二级登录页面，填写用户名和密码，并可返回选择登录方式。页面跳转保留登录后的目标页面。“使用账号密码登录”面向管理员，全部现有账号沿用此入口，保留原账号、密码、角色及资料。

学生首次通过社盟账号成功登录后，系统自动建立本站账号并直接赋予学生角色（student），随即开放学生权限对应的互动和投稿入口。后续登录按社盟返回的唯一身份标识关联同一个本站账号，本站资料、收藏、贡献记录及封禁状态随该账号保留。

## 社盟单点登录

用户选择“通过社盟账号登录”后跳转社盟完成身份验证与授权；社盟要求首次登录引导时，用户完成后继续返回本站。接入采用 OpenID Connect 的授权码流程与 PKCE（S256），请求 openid 和 profile 范围，由本站服务端完成身份验证并建立本站会话。

本站以社盟返回的唯一身份标识 sub 识别学生账号，以 name 中的真实姓名作为账号姓名及公开展示名称。每次成功登录时同步真实姓名，个人主页、账户菜单、评价作者和 Wiki 贡献者等位置使用该姓名；学生资料页将姓名显示为社盟同步信息。身份、姓名及授权响应校验通过后，系统再检查本站账号状态并决定登录结果。

用户取消授权、授权过期、身份校验失败或社盟服务暂不可用时，登录页显示对应原因并提供重新发起登录的入口。登录成功后返回用户原本想访问的本站页面；没有来源页面时进入账号设置的默认入口。

## 账号密码登录

账号密码表单使用现有用户名和密码，登录资格为管理员、运营者及全部保留的现有本地账号。用户名匹配忽略大小写，密码错误和用户名不存在时显示相同的失败提示；短时间内反复尝试会暂时限制继续尝试。表单保留用户名输入并显示登录结果。登录成功后返回原本想访问的本站页面；没有来源页面时进入默认入口。

## 退出与会话

登录成功后站点记住当前设备的会话；导航入口见[首页与公共体验](home.md)。退出登录结束当前设备的本站会话；社盟登录用户同时进入社盟登出流程，再返回本站。

用户修改本站密码、被封禁或角色发生变化时，所有设备上的本站会话都会失效，页面要求用新状态重新登录。会话过期时，当前页面保留可阅读内容，执行需要身份的操作会提示重新登录，并可回到原来的页面。

通过对应登录方式确认身份后，已封禁账号进入本站封禁提示页，显示封禁原因、封禁说明图片和最近一次申诉状态。管理员允许在线申诉时，页面提供申诉表单；其他情况显示联系运营者的说明。本站封禁状态在每次登录及需要身份的操作时生效，社盟身份验证通过的学生同样受此约束。

## 密码与账号安全

账号密码登录的账号在设置的“账号安全”区域输入旧密码、新密码和确认新密码。新密码至少 8 个字符，包含大写字母、小写字母和数字，首尾均为有效字符。系统校验旧密码及新密码规则、确认两次新密码一致后保存；校验失败时在当前页面说明原因。修改成功后立即结束全部设备会话、清除当前登录状态并通知用户重新登录，个人资料、收藏和申请记录继续保留。

用户可以主动撤销所有设备的本站会话。账号密码登录的账号需再次验证当前密码；社盟登录的学生需重新完成社盟身份验证。验证成功并确认账号状态后结束全部本站会话；验证失败或请求过于频繁时显示原因，保留原会话状态。

## 封禁申诉

被封禁用户通过原登录方式确认身份后，在本站封禁提示页查看申诉入口：学生完成社盟身份验证，现有本地账号验证本站用户名和密码。申诉入口按管理员设置的申诉资格开放，身份验证结果仅用于查看封禁信息和提交申诉。申诉理由必填，最多 500 字，可附一张图片；身份验证、申诉资格和图片格式及大小校验通过后创建申请。十分钟内重复申诉会显示剩余等待时间。

申诉提交后显示待审核状态，用户可以看到上一条申诉是待审核、已通过、未通过或已撤回。通过后账号恢复本站登录资格；拒绝后保留处理说明。申诉期间账号保持本站封禁状态。

## 个人主页

个人中心和设置在窄屏幕上使用分区导航。自己的个人中心分为主页、收藏、头衔和申请管理；用户可以在主页查看姓名或昵称、展示 ID、签名、头像、权限标签和当前佩戴头衔。社盟学生账号显示同步的真实姓名；账号密码登录的账号同时展示用户名和昵称，用户名是本站登录标识。展示 ID 是公开标识，与登录标识分开显示。

查看他人主页时只读显示对方已公开的资料、已佩戴头衔和公开收藏夹。其他人的主页没有编辑资料、佩戴头衔或管理申请的入口；访问自己的用户主页链接会回到个人中心。无效用户编号显示“用户不存在”，不泄露账号是否曾经存在的更多信息。

## 公开资料修改

账号密码登录的账号可以编辑昵称，各类账号均可编辑签名，按 Enter 或离开编辑区域后出现保存确认；按 Esc 或选择“不保存”恢复原内容。昵称要求填写且最多 20 个字，签名最多 200 个字；展示 ID 需要 3 至 24 位字母、数字或下划线，且不能与他人重复。头像从本地选择后先在当前设备压缩，再提交审核。

每次资料提交都会出现在“我的申请”，状态为待审核；审核期间公开资料仍使用旧版本。待审申请可以撤回，已通过或未通过的申请只能查看结果。成功发布的资料会在个人主页和评价作者信息中同步更新，图片处理失败或网络失败时不会留下半成品。

## 头衔

头衔页列出已经获得的头衔、颜色、说明和获得方式。用户可以选择一个头衔佩戴，也可以选择不佩戴，保存后在个人主页、评价和允许显示身份的位置更新。自动获得但尚未达成的头衔会显示进度和达成条件，不能被选择或手动领取。

查看他人头衔时只能阅读，不能替对方佩戴或取消。头衔被撤销后从可佩戴列表消失，已经显示的公开资料在下一次刷新时同步更新。

## 网站偏好

“网站设置”允许选择访问首页时默认打开首页、校园地图或菜品与食谱；选择食谱默认显示今日与明日、全部菜品、菜品评价或每周食谱。进入必吃榜时可以保存默认排序方式、默认排序顺序和默认店铺类型；这些偏好只影响自己的初始列表，不改变其他用户的列表。

Web 的网站设置与 iOS 的浏览偏好均提供“排序方式”和“排序顺序”选择，并将其作为同一账号的默认排序保存。距离、点赞数、评价数、评分和步行时间都支持“从低到高”和“从高到低”；同时保留拼音排序、距地铁最近和最新收录，选择这些固定顺序的方式时隐藏顺序控件。切换方式时采用该方式的默认顺序，具体含义、默认方向及视觉要求与[必吃榜列表](eater.md)一致。

保存成功后，同一账号在 Web 或 iOS 重新进入必吃榜时使用已保存的方式和顺序。列表中的临时选择不自动覆盖账号默认值，保存偏好也不替换已经打开的列表中的显式选择；从店铺详情返回继续保留原列表状态。Web 链接显式指定排序时优先遵循链接，具体规则见必吃榜列表。

没有已保存偏好时，默认按距离从低到高。旧账号只保存了排序方式而没有顺序时，距离按从低到高，点赞数、评价数和评分按从高到低，拼音排序、距地铁最近和最新收录保留原有含义。无法识别的默认方式恢复为距离从低到高，无法识别的顺序使用对应方式的默认顺序；固定顺序的三个选项忽略不适用的顺序值。仅打开设置或浏览列表不会改写已有偏好。

保存默认排序失败时，当前页面保留用户正在编辑的方式和顺序并显示失败提示，原有已保存偏好继续有效；重新打开设置或在另一端进入榜单时不能把失败的草稿当成已生效配置。验收时应覆盖两端相互保存后重新进入、临时排序不覆盖默认值、旧偏好兼容、链接优先，以及保存失败后重试的场景。

用户可以选择店铺详情的纵向或双栏布局，也可以交给屏幕宽度自动选择；手动布局会记住上次在详情页的切换。收藏设置可以指定进入个人中心时默认打开的收藏夹，并设置之后新建收藏夹默认公开或私密；已有收藏夹不受该开关影响。公开收藏的权限与具体规则见[校外就餐](eater.md)。

用户还可以选择是否在评价等位置显示自己的权限等级标签。普通用户没有可隐藏的更高等级时，页面会解释该设置不产生额外效果。保存失败会保留原设置并提示，重新加载不会把未保存的草稿当成已生效配置。

## 申请记录

个人中心的“我的申请”按时间分页显示资料变更、封禁申诉以及用户贡献相关申请。每项显示申请类型、编号、提交时间、摘要、当前状态和处理说明；待审核项提供撤回入口，撤回待审核的 Wiki 修改申请会同步解除对应词条的自动锁定，已经处理的项不显示撤回按钮。打开消息中的申请链接会定位并高亮对应记录，返回全部申请不会丢失当前分页。

申请列表加载失败时提供重试，暂无申请时显示空状态。申请通过后，涉及公开内容的记录提供查看目标的入口；目标被删除时仍保留申请结果和说明。

## 消息箱

登录用户从导航或设置进入消息箱。消息按时间倒序排列，可切换全部、系统类或仅未读；每页显示有限数量，滚动或翻页可继续加载更早消息。未读消息在导航中显示总数，进入消息箱不会自动把全部消息标记为已读。

用户可以逐条标记已读，也可以一次标记全部。消息包含标题、正文、重要标记、产生时间和相关对象入口；审核结果、账号变更、工单回复和系统公告都在这里汇总。相关对象已经不存在时，消息仍可阅读，但跳转会显示目标不可用的原因。加载失败或网络断开时保留已有消息并提供重试。

## 工单

设置中的“工单”要求登录后使用。新工单填写标题和内容，并选择“管理员及以上”或“仅运营者”的可见范围；标题最多 100 个字，内容最多 2000 个字。每个账号短时间内最多提交有限数量的工单，超出后显示稍后再试。

提交成功后工单显示待处理状态、编号、可见范围和提交时间。用户只能查看自己提交的工单和工作人员回复，不能修改或撤回已经提交的内容。工作人员回复后状态变为已批复，回复人、时间和正文显示在原工单下，并产生一条可跳回设置页的消息。仅运营者可见的工单不会出现在管理员的处理列表中。
