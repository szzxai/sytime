# 校外就餐与三元坊必吃榜

## 必吃榜入口与列表

“三元坊必吃榜”向访客开放。页面顶部说明收录范围以三元坊及配置的周边区域为准，并说明校园距离和地铁距离都是步行路线距离，不是地图直线距离。用户可以先看全部店铺，再通过类型和条件缩小范围。

支持的筛选和排序如下：

| 操作 | 用户可选择的内容 |
| --- | --- |
| 类型 | 使用当前榜单中已有的店铺类型，或全部 |
| 搜索 | 店名、道路、商场等关键词 |
| 校园距离 | 最小/最大步行距离，最小/最大步行时间 |
| 地铁距离 | 按店铺提供的地铁站出口步行信息理解 |
| 热度 | 点赞数、评价数 |
| 口碑 | 最低/最高评分 |
| 排序 | 距离、点赞数、评价数、评分、步行时间，以及保留的拼音排序、距地铁最近、最新收录 |

Web 中的筛选和排序会写入当前链接，刷新后保留。移动网页列表单列显示。列表卡显示店名、类型、地址、校园步行时间、地铁信息、评分、点赞数和评价数。没有结果时说明没有匹配店铺，并给出清除筛选或修改关键词的方向。

## 排序方式与顺序

Web（含桌面和手机浏览器）与 iOS 的必吃榜列表均提供“排序方式”和“排序顺序”选择，访客和登录用户都可以使用。以下五种方式均支持“从低到高”和“从高到低”：

| 排序方式 | 比较的数据 | 该方式的默认顺序 |
| --- | --- | --- |
| 距离 | 从苏州中学本部到店铺的步行路线距离 | 从低到高 |
| 点赞数 | 店铺当前点赞总数 | 从高到低 |
| 评价数 | 已公开的店铺评价总数 | 从高到低 |
| 评分 | 已公开评价形成的平均评分 | 从高到低 |
| 步行时间 | 从苏州中学本部到店铺的预计步行分钟数 | 从低到高 |

距离和步行时间都使用店铺已录入的校园步行信息，不请求用户实时定位，不按直线距离或地铁距离比较。点赞数、评价数和评分与店铺公开统计保持一致，待审核评价不参与比较。数值按实际大小排序，不按显示文本或评分显示时舍入后的数值排序。零点赞和零评价是有效数值；无评分店铺在两个方向下都排在有评分店铺之后，仍显示暂无评分，不作为零分参与比较。

原有的“拼音排序”“距地铁最近”“最新收录”继续可选，分别保持拼音正序、地铁步行距离由近到远、收录时间由新到旧。选择这三项时隐藏“排序顺序”控件，不提供与其固定顺序相冲突的选择。切换到五种可双向排序的方式时，先采用该方式的默认顺序，用户随后可以调整；只改变顺序时保持当前方式。

主值相同时保持固定次序，改变方向只改变主排序，不直接倒转同值店铺。距离相同先比较步行时间由短到长，步行时间相同先比较距离由近到远；点赞数或评价数相同先按校园距离由近到远；评分相同先按评价数由多到少，再按校园距离由近到远。仍相同时沿用名称和店铺的既有稳定次序，重复浏览或翻页不会无故跳动。

排序作用于全部匹配店铺，然后再分页或分批展示，不能只排序当前可见的一页。改变方式或顺序后，Web 回到第一页，iOS 恢复初始展示批次；搜索关键词、类型及各项范围筛选保持不变，匹配店铺总数不因单独改变排序而变化。选择“清除筛选”后恢复全部类型、空关键词、无范围限制和距离从低到高，但不修改账号已保存的默认偏好。

Web 链接同时保留排序方式和顺序，刷新、分享及浏览器前进后退均能恢复对应选择。链接明确指定的排序优先于账号默认偏好；只指定方式时采用该方式的默认顺序，只指定顺序时应用于账号默认方式，没有账号偏好则应用于距离。固定顺序的三个旧选项忽略链接中的顺序。旧链接没有顺序时保留原有排序含义；无法识别的方式恢复为距离从低到高，无法识别的顺序恢复为对应方式的默认顺序。账号默认偏好的保存规则见[账号与个人空间](users.md)。

Web 与 iOS 从店铺详情返回列表时保留当前排序和筛选。排序加载或失败时沿用现有加载、错误和重试反馈；失败不能显示为没有匹配店铺，也不能将旧次序误报为新排序已完成。重试保留用户选择，快速连续切换时最终只展示最后一次选择对应的结果。

### 排序控件与视觉一致性

列表和默认偏好设置中的新增控件必须沿用所在端现有界面风格。Web 使用现有表单选择器的字体、字号、文字层级、颜色、圆角、边框、间距，以及悬停、焦点和禁用状态；iOS 使用现有原生选择器与设置表单样式。两端使用一致的“排序方式”“排序顺序”及选项文案，各自保持与其他页面相同的视觉效果，不引入独立的装饰风格。

桌面端在现有排序区域排列控件，窄屏按可用宽度自然换行，不挤压类型筛选、不截断选项、不产生横向溢出。浅色和深色主题均与邻近控件一致且清晰可读，主题切换不改变当前排序。键盘和屏幕阅读器可以识别控件名称、当前选择与结果更新，iOS 支持 VoiceOver，焦点反馈与现有控件一致。

### 排序验收场景

- 五项指标的十种方式与顺序组合均能正确排列；三个保留选项仍按原有规则工作。
- 结果超过一页或一个初始批次时保持全局排序正确，同值、零计数、无评分和评分显示精度不影响既定规则。
- 改变排序保留筛选并重置展示进度；Web 链接恢复、浏览器前进后退和 iOS 详情返回均能保留对应状态。
- 排序失败与空结果可以区分，重试不丢失选择，连续切换不会被较早的结果覆盖。
- 桌面、窄屏、浅色、深色及辅助功能下，新增控件与所在端既有界面保持一致。

## 周边地图

列表旁提供店铺分布地图。用户可以拖动、缩放、点击放大/缩小和回到姑苏区全域；地图标记显示店铺位置和摘要，点击后可以打开对应详情。地图底图不可用时，列表仍然可读，并说明地图服务暂不可用。地图中心或缩放值超出允许范围时，页面回到安全范围并给出提示。

## 店铺详情

店铺详情包含：店名、类型、地址、位置补充说明、店铺坐标、从苏州中学本部出发的步行距离与时间、从指定地铁站出口出发的步行距离与时间，以及可选的大众点评链接。用户可以点击“在高德地图打开”前往外部地图。外部链接应在新页面打开，返回平台后保留原详情状态。

详情页显示互动摘要：点赞数、评价数、参与评分的人数、平均评分和当前用户的点赞/评价状态。店铺有菜品目录时展示菜名与价格；没有目录时明确显示“暂无菜品”，不能误认为店铺没有菜单。

评价区分页显示同学评价，按最近更新排序。评价卡显示作者、头像、身份和头衔（存在时）、星级、文字、用餐人数、总价、每人花费、图片和更新时间。总价与人数都存在时计算每人花费；缺少任意一项时不编造金额。评价配图可以打开查看大图。

无效店铺编号、已删除店铺和不存在店铺均显示“店铺不存在或已被删除”，并提供回到必吃榜的入口。详情请求失败显示可重试的错误状态。

## 点赞和店铺评价

登录后具备学生及以上权限的用户可以点赞或评价。访客点击互动按钮先看到登录入口，学生通过社盟账号登录后可继续互动。学生点击点赞后，按钮立即显示已点赞和最新数量；再次点击取消点赞。服务失败时恢复原状态并说明失败原因。

评价表单包含一到五星、可选文字（最多 500 字）、可选用餐人数、可选总价和可选 JPG/PNG 图片。图片最大 2 MB，文件不是有效图片、格式不支持或超过大小时，在图片字段附近显示具体原因。总价不能为负数，用餐人数必须为正数，评分只能是一到五。

一个用户在一家店铺只能保留一条当前评价。首次提交显示“评价已提交审核”；修改自己的评价时显示“评价修改已提交审核”，审核期间继续展示旧评价。通过后新版本替换旧版本，删除图片的选择也要在通过后才生效。删除自己的公开评价需要二次确认；删除后该评价从公开统计中消失，并撤回尚未处理的相关申请。

评价通过后才计入店铺评价数、评分人数和平均分。评价被拒绝时旧版本继续存在（如果有旧版本），新内容不会公开；拒绝原因会进入消息箱。页面不展示别人的待审核内容。

## 推荐新店铺

具备学生权限的用户可以打开“添加店铺”。表单要求填写店铺名称、地址、类型、地图坐标、校园距离和步行时间；可以补充位置说明、大众点评链接、地铁站、出口、地铁距离和步行时间。类型可以从已有类型选择，也可以填写不超过八个字的自定义类型。

位置预览地图显示用户输入的坐标。用户可以从高德地图拾取器复制坐标，也可以根据学校本部或地铁出口测算步行路线后填入；测算结果填入表单后仍需用户核对。坐标必须位于当前收录区域内，校园和地铁距离、时间不能为负数，链接必须是允许的店铺链接格式。

提交前检查必填项、格式、区域范围和重复店铺。重复时保留已存在店铺编号并提供查看入口。每位学生每天最多推荐十家；已有相同店铺的待审核申请不能再次提交。提交成功后店铺不会立即出现在公开榜单，用户可在个人中心查看申请状态、审核结果和拒绝原因。

## 收藏夹

登录用户可以在榜单卡片或店铺详情点击收藏，把店铺加入已有收藏夹或新建收藏夹。收藏夹名称必须填写，重复收藏同一家店时显示“已在收藏夹中”，不会产生重复条目。用户可以取消收藏，但取消只影响当前收藏夹。

收藏夹可以改名、在公开与私密之间切换、分页查看店铺，并设置个人中心进入时的默认收藏夹。新建收藏夹默认采用账号中的“新建收藏夹默认公开”设置，但用户可以只改变本次新建的公开状态；已有收藏夹不会被联动修改。

桌面端通过侧栏切换收藏夹，移动端使用顶部选择器。普通用户只能创建和使用私密收藏夹；学生及以上身份可以公开收藏夹。公开收藏夹可在用户主页被他人匿名只读浏览，私密收藏夹只能本人查看。查看他人收藏夹时隐藏公开开关、编辑按钮和私密收藏夹名称。店铺被删除后，收藏条目保留并显示已删除占位，用户仍可将其移除。
