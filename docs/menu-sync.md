# 官网每周食谱与 Gemini 同步

更新：2026-10-31。抓取器作为现有 Monorepo 的 `apps/api/src/domain/menu` 领域模块维护，与页面共享数据库和发布规则；识别在独立 Node worker 线程运行。当前规模无需独立 Repo、Python 服务、浏览器爬虫或额外队列服务。

## 首次安装与启用

Node.js 24 LTS 推荐，最低 22.13。执行 `npm ci`、`npm run build`。新库菜单为空，不再启动导入历史种子。迁移 `0001_menu_rebuild` 仅一次删除上线前的菜品、供应、评价、菜单任务与配置，重置食谱默认页；保留账号、店铺、收藏、消息和头衔。正常重启不会清除新评价。

只通过服务器环境变量配置，站内没有菜单管理、上传、补图或人工导入面板/API。

```env
GEMINI_API_KEY=服务器密钥
MENU_PROVIDER=gemini
MENU_MODEL=gemini-flash-lite-latest
MENU_SYNC_ENABLED=true
MENU_SYNC_MODE=weekend
MENU_SYNC_TIME=08:00
```

也支持 MENU_API_KEY，优先于 GEMINI_API_KEY。compatible 提供商另配置 HTTPS MENU_BASE_URL；openrouter 使用固定官方地址。Key 不写数据库或浏览器，旧后台加密配置不再读取。修改环境后重启。没有 Key 时同步关闭，公开菜单仍可读取。

构建后可运行 `npm run menu:setup`：真实测试图片能力并执行首次任务，失败非零退出。普通启动由常驻任务每15秒检查计划；默认上海周六/日08–22点每小时、周一08/12补查，兼容 daily 的 MENU_SYNC_TIME。任务时段持久去重，租约避免多进程重复。启动时不追补本次配置生效之前的时段；失败在后续时段重试。服务器需持续运行并能访问学校与提供商。

## 如何发现最新食谱与图片

列表：<https://www.szzx1000.cn/e/action/ListInfo/?classid=36>。只接受该学校域名、固定栏目和合法文章编号，按栏目顺序找最新文章。首次只取最新一期，之后按锚点发现新文章，最多扫描十二页；实际后续页使用 `/e/action/ListInfo/index.php?classid=36&page=1`，page 从零计数。

本次实测文章：<https://www.szzx1000.cn/e/action/ShowInfo.php?classid=36&id=11427>，供应日期为 2026-10-26 至 10-31。图片位于 `#newstext img` 的 `data:image/png;base64,...`，并非单独图片下载地址；原始图 3001×3890，解码约 528 KB。透明背景先铺白，避免黑底影响识别。保存 HTML、图片摘要及私有诊断以便追溯。

遵守 robots，设置超时、大小上限、有限网络重试和请求间隔；不跟随任意重定向。当前仅自动读取正文内联图片，外部图片或附件不猜测抓取；站点格式改变时失败并保留旧发布结果。故障恢复通过服务器代码和离线工具核对完整原图，网站不接收补图。

每轮最多识别十篇，较新来源优先；重查最近两篇摘要。内容未变且已成功发布则不请求模型。失败来源仍会重试，不能把“曾发现文章”视作“已发布”。

## 识别与发布边界

官方 `@google/genai` SDK，高分辨率图片输入、JSON Schema 输出、本地 Ajv 再校验。检测横向标题和网格，从当前图片实测标题、浅色网格、非等宽日期列和午晚餐边界；将密集大表按实测日期与餐次裁开，不假设每日列宽、行数或单元格高度相同；每个分块保留左侧合并餐次/档口标签，并附清晰的完整标题地点。较小表直接读取，物理分区不适用时采用模型布局。

Gemini 返回按日期、餐次、地点集合、分类分组的紧凑结果。价格先逐字读取为 `price_text`，程序转换：`15元/12个` 为 15，`6元/小份` 为 6，`1元/1.5元` 为 null，免费为 0。程序展开多个明确地点，再输出正式八字段：`date, weekday, time, place, group, name, price, spicy`。辣椒仅依据原图图标；面档约定午晚餐；大课间为空餐次，分类为大课间。清晰白格不输出。

明确写出地点的风味、现煮和括号内小吃档口使用该档口地点；纯“二楼”不能覆盖完整校区名，统一学校专名“泮水居”，避免各日期地点不一致。每个分块复核返回完整修正数据，程序要求归一化结果收敛；最多三轮仍不一致则失败。Schema 错误另有一次格式修复。输出截断、日期/字段无效、读不清或复核失败，整篇不发布，诊断保留已读分块。每篇最多二十分钟、一百次请求；429、网络和服务端错误有限退避。模型自检不能证明准确率，尤其不保证未来版式一定成功；失败可自动重试，也可在服务器私有目录核对原图和问题。

数据库事务替换单篇供应；稳定菜名共享菜品 ID，后续更新保留评价。每周、日期、餐次、地点、分类和价格保留为供应记录。公开页面只读取成功发布的数据，模型原文、密钥和诊断不提供 HTTP 访问。

## 页面与接口

- `GET /api/menu?source_id=...`：默认最新供应周；all=1 可读取全部已发布周且不得和 source_id 同传，返回周次、当前周、供应（含真实平均分与评价数）和最近任务状态；未知周返回 404，重复来源参数拒绝。
- `GET /api/dishes`：当前有供应的菜品及评分。
- `GET /api/dishes/:id`：菜品真实评分及最近 100 条供应；历史菜品仍可评价。
- `GET /api/dishes/:id/reviews`：每页二十条评价。
- `GET/POST /api/recipes`：公开已批准评价列表，以及学生提交待审评价；评分必须 1–5，菜名由服务器按菜品 ID 确定。
- 旧每周图片列表、上传、删除及旧每周评价接口已移除；数据库旧图片表已删除。
- 所有 `/api/admin/menu-sync/*` 和旧图片写接口均返回404，账号角色不构成例外。

## 凭据与持久化

持久化 data.db、uploads、.private 与环境配置。Key 仅由进程环境注入，不下发浏览器、写Git或普通日志；历史 menu-master.key 不再用于配置读取。原图、缓存和诊断在私有目录，静态访问禁止。现有菜单、任务与缓存保留，账号重建不删除供应记录。

验证结果见 [菜单实测记录](menu-validation.md)、[UI 验收](ui/acceptance.md) 和根目录 [MAP.md](../MAP.md)。

## 双栏展示与偏好迁移

默认双栏仅按所选日期、校区和两栏独立餐次筛选；原生日期输入跨周读取对应来源，不将未公布日替换为最近供应日。同款菜品合并显示地点，但数据库仍保留独立供应，评价仍归属稳定菜品 ID。标题、卡片及精确布局以 docs/ui/pages/recipe.md 为准。0002_menu_daily_view 只把旧 weekly 默认迁移到 daily，保留菜单和评价以及其他明确偏好；新注册默认 daily。原始基线 schema 的 all 默认属于历史结构，不是当前注册行为。
