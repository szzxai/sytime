# 文案规范 · copy.md

> 所有界面文字的唯一依据。写任何按钮、提示、错误之前先来这里找；找不到再按本页规则自拟，并回填到本文件。

## 1. 基本规则

1. **对用户称「你」**；不称「您」（唯一例外：封禁提示保留「您已被封禁，如要解封请线下联系超级管理员」原句式）。
2. **按钮 = 动词短语**：登录、注册、发布帖子、发布回复、写评价、保存修改、提交工单、添加店铺、添加菜品、确认封禁、退出登录。禁止「点击这里」「GO」「提交按钮」。
3. **确认按钮写具体动作**（删除 / 封禁 / 退出登录），不写「确定」；只有纯信息确认才用「确定」/「我知道了」。
4. **一个界面一种语气**：陈述句，句号结尾的完整句用于说明；短语（不带句号）用于按钮、标签、状态。
5. 数字与英文两侧留半角空格：「红烧牛腩面 12 元」「Node.js 24」「JPG / PNG」。
6. 界面用中文标点；列举用「、」；省略用「…」（单字符）。
7. 禁止：网络流行语、感叹号堆叠（最多 1 个/屏）、emoji、翻译腔（「我们很抱歉给您带来不便」→ 直接说发生了什么和怎么办）。
8. 错误信息三段式（能全则全）：**发生了什么 + 为什么（可选）+ 你可以怎么做**。
9. 名称：顶栏只显示青柠切面图标，其他位置的站名为「拾光酥糕」；顶栏使用短名「地图 / 论坛 / 菜谱 / 必吃榜 / 更新公告」，其他功能文案按页面需要使用全称「校园地图 / 菜谱评价 / 三元坊必吃榜 / 学生认证 / 个人中心 / 设置 / 管理后台 / 消息箱 / 头衔」。

### 5.6 前端预校验文案（图片上传，`UI.upload` 自动生成）

- 格式错误：「仅支持 JPG / PNG 格式的图片」
- 大小超限：「图片不能超过 2 MB（当前 1.8 MB）」（上限随场景：头像/评价/菜品 2 MB；每周食谱/封禁/工单 5 MB）

## 6. 限流倒计时（429 + retry_after）

界面组合（三件套，全部要做）：

1. `alert--warning`：`提交太快了，还需等待 01:30 才能再次提交。`（时间用 `UI.formatCountdown(retry_after)`）
2. 提交按钮禁用并显示：`等待 01:30`，用 `UI.countdown(retry_after, n => btn.textContent = '等待 ' + UI.formatCountdown(n), () => btn.disabled = false && btn.textContent = 原文案)` 每秒刷新。
3. 页面文档对应「状态矩阵」里的「限流」行引用本节。
