# 消息箱 · inbox.html

更新：2026-10-31。继续保留系统/头衔分类、未读筛选、分页、单条/全部标记已读和导航未读数。

新的审核工作流在提交、通过、拒绝、竞争身份自动拒绝、撤回、解绑、封禁/解封、角色变化、工单提交和回复时写入系统通知。提交同时通知有权处理的管理员/运营者；仅运营者可见工单不会通知普通管理员。处理决定与发布在同一数据库事务完成，避免内容与通知分离。

消息时间使用共享次级正文颜色，确保明暗主题对比度；消息只允许本人读取/标记。封禁会立即撤销会话；通过申诉解封后可重新登录读取处理通知。未增加邮件或站外发送能力。

## 实现与验证

当前实现：React + TanStack Query/Router，Hono + SQLite/Drizzle。权限以数据库当前角色、状态和有效会话为准，隐藏入口不能替代后端校验。验证命令、实测结果与限制见根目录 [MAP.md](../../../MAP.md) 最新记录，以及 [验收记录](../acceptance.md)。

## 2026-10-31 跳转与自动已读

通知通过 messages.target_kind / target_id 关联审核或工单，由后端按当前权限生成站内目标地址。批准的菜品/店铺评论直接定位对应评论卡，即使不在第一页也单独加载、聚焦并强调；未通过、撤回或公开评论已删除时，跳本人私有申请详情，显示原文和原因。管理员待办跳对应审核详情；工单跳相应设置或后台面板。

鼠标、Enter 与空格使用相同打开逻辑，先等待服务端标已读成功再跳转。申请通过/拒绝、竞争拒绝、撤回、解绑或工单回复时，旧“已提交/待处理”通知对所有接收者自动标已读；新产生的结果通知保持未读直到用户查看。消息列表与未读统计会复核已处理状态，列表每 30 秒刷新。旧通知仅在能唯一匹配原系统文案和申请时补关联，不猜测有歧义的历史通知。
