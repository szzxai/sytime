# 菜品详情 · dish.html

> 更新：2026-10-24。入口为 `dish.html?id=<菜品编号>`，默认站点壳，`data-nav="recipe"`。本页是菜单目录的详情，不是原「菜品评价」栏的替代页。

## 页面结构

1. 原生「返回全部菜品」链接，目标为 `recipe.html?view=all`。
2. 页面标题为目录规范菜名，长名称可换行；摘要显示真实平均评分与评价总数。
3. 「写评价」打开共用对话框，预选当前菜品；访客先提示登录并保留回跳地址。
4. 「评论与评价」显示完整文字、作者昵称、头像、权限标签、佩戴头衔、发布时间及评分；可选配图使用现有图片查看器。
5. 按新到旧每次加载 20 条，加载更多保留先前内容，末页收起入口。评论不截断，保留换行并转义用户文本。

没有评论时显示「暂无评分」「共 0 条评价」及分享邀请，不显示虚构的零分。没有商品介绍、价格、供应时间、店铺或默认菜品图片；展示的图片只来自用户评价。

## 数据与兼容

| 请求 | 契约 |
| --- | --- |
| `GET /api/dishes/:id` | `{dish}`，目录字段加 `reviews_count`、`rating_avg`；平均分保留一位小数，无评价为 null |
| `GET /api/dishes/:id/reviews?offset=0` | `{reviews,total,offset,has_more}`，每页 20 条，按发布时间和编号倒序；包含统一作者信息 |
| `GET /api/dishes` | 共用写评价对话框的已有菜品候选 |
| `POST /api/recipes` | 登录后提交 `dish_id`、整数评分及可选评论/图片；菜名由服务端确定，不接受仅凭名称发布 |

详情和评论只接受有成功供应记录的目录菜品；ID 无效、不存在或已不在目录中返回 404。评论只统计该 `dish_id` 的非每周记录，两个读取成功响应均禁止缓存。偏移量必须为 0–1000000 的整数字符串，客户端按接口页偏移推进并去重展示，避免重复记录影响后续页码。

启动时在目录初始化后，为原评价表增加可空外键和索引。旧非每周评价按 NFC、空白和大小写归一名称补关联；不改旧菜名、不删除无法匹配记录、不覆盖已有关联、不关联每周评价。原全站「菜品评价」栏仍显示旧内容，卡片、排序和分页不变。

## 写评价与选菜

- `public/js/dish-review.js` 生成两页共用的原生对话框。当前详情可预选；用户可重新搜索并选择其他已有菜品，发布成功后跳到所选菜品详情。
- 输入支持菜名子串、完整拼音和首字母；未筛选和筛选后的首批均最多 50 条，点「显示更多」每次追加最多 50 条，保留已有结果、顺序及滚动位置；全部显示后隐藏按钮，状态报告总数与已显示数。更换关键词、清空搜索或收起再展开恢复首批。只输入文本不会建立选择，即使与目录名称完全相同也需点选或回车确认。
- 选择后保存隐藏的菜品 ID，任何文本编辑立即清空；服务端独立校验 ID 并取规范名称，不能用伪造文本新增菜品。
- 鼠标点选、上下方向键与回车可选中所有已显示候选；Escape 在输入框和候选按钮上都先收起候选，Tab 可到达「显示更多」或重试按钮但不选择菜品，移出选菜区域收起。最后一批追加后按钮消失时焦点回到输入。中文输入法组合期间不提前选中，组合框保留展开状态、活动后代、列表框及选中项语义。
- 菜品加载、无匹配、失败与重试有状态提示，长名称不受原 20 字限制；候选与输入使用完整系统中文字体。
- 评分默认五分，评论最多 500 字，选填 JPG/PNG 图片不超过 2 MB。取消或失败保留草稿；成功重置表单与图片，刷新当前详情的评分、评价数和首批评论。

## 状态与适配

- 初始加载为骨架；详情与首批评论网络失败各提供重试。追加页失败保留已有评论，允许再点加载更多。
- 无效或过期链接显示「没有找到这道菜品」、解释与返回目录入口，不显示写评价按钮。
- 手机和桌面沿用公共标题、细边框卡片、主题令牌；摘要和作者行可换行，评论自动折行，配图最大 24rem 且不超出容器。手机写评价为底部面板，候选列表自身滚动。
- 目录与返回入口均为原生链接；对话框沿用焦点管理、关闭和恢复逻辑，图片查看器支持键盘关闭。不改变其他页面的主题或全站字体优先级。
