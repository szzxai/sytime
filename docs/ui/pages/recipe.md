# 菜品与食谱 · recipe.html

> 状态：#4 统一 UI；#5 增加独立目录与三个页签。壳：默认，`data-nav="recipe"`，容器 `container`。

## 视图

| 页签 | 内容 | 操作 |
| --- | --- | --- |
| 全部菜品 `view=all` | 搜索、A–Z 目录、数量与更新时间 | 字母跳转与清除搜索 |
| 菜品评价 `view=reviews` | 原有图片/菜名/评分/评论/作者/时间卡片 | 登录后写评价，加载更多 |
| 每周食谱 `view=weekly` | 原有按供应日期折叠的上传图片 | 查看大图，有权用户删除 |

明确 URL 优先于账号默认 `recipe_default_view`；无 URL 时读取账号设置，回退 localStorage，再回退 all。用户已经切换后，较晚返回的默认设置请求不会覆盖当前视图。切换取消旧请求并更新 URL，搜索词在各视图间保留。

三个按钮保留 tab 语义及键盘切换，共享内容区为 tabpanel，`aria-labelledby` 指向当前按钮。菜品目录规范见 [dishes.md](./dishes.md)。

## 评价

仍使用 `GET/POST /api/recipes`。评价按名称拼音显示，每批二十条；一条评价对应一张卡，不自动绑定菜单目录 ID。评价卡保持图片占位、原评分星、评论转义和用户行。

「写评价」仅在评价页签出现。游客点击显示登录提示；登录后打开统一对话框，菜名必填、评分默认五分、评论与图片选填。JPG/PNG 上限 2 MB，上传预览和既有校验保持一致。失败保留填写内容，成功关闭并重载列表。空评价显示写评价或去登录操作。

钩子：`reviewsBtn`、`writeAction`、`writeBtn`、`reviewDialog`、`recipeForm`、`name`、`comment`、`image`、`recipeSubmit`、`moreBtn`。

## 每周食谱

仍使用 `GET /api/weekly-menu` 及已有管理上传/删除接口。按起止日期折叠，本周默认展开；显示上传者与时间，图片可滚轮/双指缩放、拖动和关闭。上传者或 super_admin 以上可删除，操作需要统一确认。

菜单自动同步结果供独立目录使用，不覆盖手动上传的每周图片。无图片显示等待管理员上传，失败提供重试。
