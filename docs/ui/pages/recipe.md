# 菜品与食谱

更新：2026-10-30。入口 /recipe.html，当前实现 RecipePage.tsx、MenuDaily.tsx、MenuPage.css。

## 默认双栏

默认“今日与明日”，左栏标题严格为“今天我吃了…”，右栏“明天吃什么？”，标题使用 400 常规字重，不附日期。左上角灰色日期可打开原生日历；星期打开所选日期所在周的七天菜单，校区按钮在本部和正谊校区间切换。列中的今天/明天相对于左上所选日期，相邻天即使跨周也分别读取对应的已发布食谱。未发布日期显示空状态，不偷换成最近供应日。

两栏餐次独立，均默认午餐；可选早餐、晚餐、夜宵、课间加餐。选择写入 URL，详情返回保留日期、校区、餐次和滚动位置。同日期、所选餐次与校区内的同款菜品按稳定 dish_id 合并为一张卡，去重地点用“和”连接；价格不同则分别展示，不伪装为未注明。

所有菜品在同一层平铺，不设地点分区标题。风味/现煮先、小食/面档/点心次之、其余随后。地点写在卡片灰字内；风味菜不再显示分类标签，普通菜可显示小食、大荤等简短标签。显示真实星级与评价数，未评价不虚构评分；点击菜名进详情，评价按钮预选菜品。页面不放学校原食谱链接。

层级以间距建立：宽屏两大栏、栏内两列菜品，手机上下堆叠；默认卡片无分割边框。右上仅三个同尺寸线条图标按钮，分别为双栏、周视图、全部菜品，带可访问名称、选中状态与键盘焦点。

## 保留周视图与高级筛选

第二种视图保留周次、日期按钮、地点、餐次和搜索，沿用按餐次/地点/分类组织供应的周视图。第三种“全部菜品”默认跨全部已发布周，提供周次、日期、地点、餐次、分类、辣椒、最低评分、价格上下限、菜名/拼音/首字母筛选；按菜品 ID 去重，可进详情和写评价。旧大家的评价仍可从高级页入口及原 reviews 深链接访问。

URL 保存 view/source_id/date/campus/left_meal/right_meal/filter_date/place/meal/category/spicy/rating/min_price/max_price/q。新注册默认 daily；一次迁移将旧自动分配的 weekly 默认改成 daily，保留原 all/reviews 偏好，迁移后用户仍可在设置明确改回周视图。正常重启不再次改写偏好或菜单数据。

公开数据每 60 秒刷新。加载、错误重试、无数据和无匹配有明确状态；数据仅来自成功发布菜单。默认页不展示后台技术细节。来源和私有诊断保留在后台，菜品详情的供应记录可追溯。

接口与识别见菜单同步文档，最新验证见 UI 验收和根目录 MAP。

### 视口相对位置补充

三种视图共用全视口正文宽度，统一左右 3.2vw（24–72px）内边距和顶部 16px；两栏标题位于各自栏中心，顶部日期与导航之间不保留大块外层空白。2048px 专项断言左右标题中心分别低于 28%/高于 72% 视口，顶部日期距顶栏不足 40px，标题距顶栏不足 180px；手机仍为上下两栏。周视图和高级页沿用同一外层容器及顶部栏，保持各自内容与筛选；切换器的坐标和按钮尺寸不随视图变化。手机顶部为日期换行预留一致高度，其他视图也保留相同空间。


### 2026-10-30 · 视图切换与评价间距

双栏、周视图、全部菜品以及兼容的评价列表共用 menu-page.container，不再仅对双栏解除宽度限制。顶部栏用两列网格固定右侧切换器，左侧日期/标题在自身范围换行；同一视口下切换器坐标、尺寸、正文左右边界和顶部栏高度一致。评价使用独立 DishReview.css，去除重复的选菜说明和默认评分说明，保留输入占位、真实校验及五分初始值；桌面弹窗最大 34rem，手机仍为底部面板。字段间距桌面 24px、手机 20px，星级点击区域 44px，评论与图片之间保留清楚间距，操作区与正文分开。
