# 全部菜品 · Issue #5

> 入口：`recipe.html?view=all`。当前实现以用户确认的 [计划](../../issue-5-plan.md) 为准。

## 页面结构

「菜品与食谱」页面含全部菜品、菜品评价、每周食谱三个页签。全部菜品显示搜索框、数量与更新时间、A–Z 分组列表及右侧索引。名称可换行，索引只出现有结果的分组。目录为独立菜品实体，评价记录继续在「菜品评价」页签显示。

本轮没有菜品详情页、店铺、评分聚合或菜品与评价的自动关联；目录行只展示原始名称。

## 数据与排序

`GET /api/dishes`：

```json
{"dishes":[{"id":12,"name":"重庆小面","initial":"C","pinyin":"chongqingxiaomian","pinyin_initials":"cqxm","sort_key":"chong qing xiao mian"}],"meta":{"total":1,"source_count":1,"records_count":1,"updated_at":1790812800000,"last_sync_success_at":null}}
```

排序在 Node 中统一完成：A–Z、#、完整拼音、名称归一键、稳定 ID。前端不重新排序，不使用浏览器 Collator 决定目录位置。名称归一采用 NFC、去两端空白、合并空白、大小写归一；显示保留首次写法，不转换繁简体或拆分套餐。

历史种子和新识别都使用同一 `pinyin-pro` 路径及词组覆盖。目录只显示至少存在一条成功供应记录的菜品；来源更新不会重排已有实体 ID。

## 搜索与访问

- 菜名子串、完整拼音和拼音首字母均可搜索，拉丁输入不区分大小写，可含空格。
- 输入防抖 250ms，中文 composition 期间暂停；结束后更新。
- 仅对名称中的原文命中段添加 `mark`，其他文本转义，拼音命中无需高亮汉字。
- 清除恢复全量并聚焦输入框。结果仍按原有 A–Z 顺序分组。
- URL 保存 `view`、`q`，刷新可恢复，明确 URL 优先于账号默认视图。无 URL 时沿用账号 all/weekly 设置，all 对应目录。
- 搜索结果数用状态文本和屏幕阅读器播报；索引为真实锚点，当前分组用 `aria-current` 标识。

## 状态与适配

首次请求为行骨架，失败为中文提示及重试；空目录显示等待同步，搜索无结果提示尝试菜名、拼音或首字母。目录不显示「写评价」按钮；切换评价页签后恢复。

360px 与 1280px、明暗主题使用现有令牌与组件。右侧索引占位不覆盖名称，长名称换行，不发生页面横向滚动。URL 输入作为数据处理，不插入可执行 HTML。

实现：`public/recipe.html`、`public/js/pages/recipe.js`、`lib/menu/schema.js`、`lib/menu/store.js`。测试包括初始 1,243 菜品、拼音搜索、中文高亮、无结果、清除聚焦、刷新恢复、手机/桌面 axe 扫描及既有评价与每周图片流程。菜单来源和同步设置见 [运维手册](../../menu-sync.md)。
