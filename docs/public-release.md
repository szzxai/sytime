# 公开仓库准备与复验

更新：2026-10-31。

## 公开边界

公开的是源码、迁移、公开静态素材与可复现的测试，不是运行站点的数据副本。

| 内容 | 处理方式 |
| --- | --- |
| `data.db`、SQLite journal/WAL/SHM、数据库备份 | 本地保留并忽略；从所有本地可达分支的历史移除 |
| `uploads/`、学生资料、会话、审核、工单、用户评价 | 上传文件不跟踪；其数据库记录随运行库一起排除 |
| `.env`、`.env.*`、`.private/`、私钥与证书容器 | 禁止跟踪；仅 `.env.example` 的空值和占位值可公开 |
| 调试日志、测试输出、系统杂项、临时文件 | 清理并忽略；历史调试输出一并移除 |
| `szzx-menu.skill` | 可再生成的技能包，不再跟踪；源文件保留在 `skills/szzx-menu/` |
| `data.json` | 保留：旧地图兼容用的公开地点和几何数据，没有账号或业务记录 |
| `data/shops-config.json` | 保留：公开地图坐标、范围和来源配置，没有高德凭据或用户记录 |
| `data/menu-bootstrap.json`、菜单测试样本 | 保留：学校已公开菜单的历史转录及来源，用于隔离测试；不是运行数据库导出，不会在新部署时自动发布 |
| `tests/fixtures/review-shot.png` | 保留：100 字节的人工测试图片，不是用户上传或屏幕截图 |
| 字体、Leaflet、校园及品牌素材 | 保留，随附已有第三方许可和地图来源；不要将第三方素材解释为项目原创授权 |

`data/` 新增文件默认会触发公开检查，需要先审查来源和内容再明确调整白名单。文件扩展名不是唯一依据，检查还识别改名后的 SQLite 数据库文件头。

## 本次历史清理

- 经维护者明确同意，先在仓库外的私有备份目录保存完整 Git 目录、可验证的全引用 bundle 和工作区压缩包。包含本机凭据、运行数据和旧历史的备份禁止上传、推送或放入公开附件。
- 在独立镜像中使用 `git-filter-repo` 清理 `data.db`、整个 `uploads/`、两份服务日志、两份测试输出及生成技能包，再替换本地 Git 元数据。保留当前 `main` 分支、已有其他分支、远端配置与所有工作文件，不创建项目分支，不自动提交。
- 原历史有 36 个可达提交、12 个不同的数据库快照和 6 张上传图片；首次清理后为 34 个可达提交，移除了仅改变被清理文件的空提交。提交编号发生变化。随后单独备份并清理远端快照，保留远端比本地多出的地图修复提交；恢复清理后的远端跟踪引用后，共 35 个可达提交。本地 `main` 未自动合并该提交，后续发布须先整合。
- 替换 Git 元数据前后逐文件核对 SHA-256，257 个文件一致，包括未提交源码、运行数据库、本机密钥和上传图片。运行数据没有清空或重建。
- 备份位置及脱敏审计报告记录在本机 `.private/public-audit/`。备份只供恢复，不能重新合入清理后的分支；协作者也不能把旧历史 merge 回来。

## 可重复检查

```bash
npm run test:public-safety
npm run public:check
npm run public:check:history
npm run build
npm run test:backend
npm run test:deploy
npm run typecheck
npm run lint
npm run format:check
npm run test:menu-skill
npm audit --omit=dev
```

- `public:check` 检查 Git 跟踪和可加入的未忽略文件，并复查与工作区不同的索引内容，避免工作区已改安全、暂存区仍有凭据的情况。
- `public:check:history` 额外检查所有本地分支、远端跟踪引用和标签的文件路径及历史 blob，不只扫描最新提交。发现问题退出 1；无法完成扫描退出 2。
- 门禁检测私有目录、数据库、日志、私钥、常见服务 token、JWT、密码哈希、带密码的连接地址、高德 Key 和个人主目录路径。仅输出规则、路径、行号及必要的对象编号，不输出匹配值。模式检测不能证明没有所有形式的敏感信息，仍需人工检查新数据和附件。
- 使用独立 Gitleaks v8.30.1 扫描待公开源码及全引用历史。`.gitleaks.toml` 继承全部默认规则，仅对 `tests/` 中已审阅的一个固定人工测试密码进行精确例外；没有忽略整个测试目录或关闭通用密钥规则。
- `.github/workflows/public-safety.yml` 在 push、pull request 和手动触发时获取完整历史，以只读权限运行门禁、其回归及 Gitleaks；不安装业务依赖，不读取生产凭据，不上传扫描报告。
- 技能包改为从源文件生成再测试，需要 Python 3；Windows 若只有 `python` 命令，可用 `python tools/build-menu-skill.py` 和 `python tests/menu-skill.py` 执行同样验证。

## 新安装与部署

开发和生产构建步骤见 [架构说明](architecture.md)。新部署使用 `npm ci --include=dev`、`npm run build`、可选 `npm prune --omit=dev`、`npm start`，按 `.env.example` 配置本机环境。显式安装构建依赖，支持预设 `NODE_ENV=production` 的机器。生产设置独立随机 JWT 密钥、准确的 HTTPS 站点地址及所需第三方凭据。空数据库由迁移创建；运营账号通过 `npm run account:operator` 在服务器创建。没有默认运营账号，也不随源码提供登录凭据。

真实环境独立持久化 `data.db`、`uploads/`、`.private/` 与环境配置。数据库升级或发布前先停写并备份。不要将整份工作目录、备份 bundle 或本机压缩包作为源码发布；忽略规则不能保护手工上传的附件。

## 改为 public 前的远端步骤

本次只清理本地 Git，没有推送、创建公开仓库、修改可见性或重写远端分支。远端仍保留原历史，不能直接切换为 public。

1. 提交并复验本次源码、忽略规则、CI 与文档改动；确认没有把运行库、上传文件、私有报告或备份强制加入。
2. 暂停协作写入，核对远端分支、标签、Release 附件、Actions 日志和产物、PR 引用及其他克隆，确定替换范围。本次远端引用清单有 `main` 和 `feature/ui-redesign` 两个分支、没有标签；两个分支都必须处理，不能只更新 `main`。
3. 经单独授权后，将清理后的分支以明确的 lease 替换远端对应引用；不要用含私有备份引用的镜像推送。推送前再次核对远端是否有新提交，避免覆盖他人工作。
4. 从远端重新克隆，在没有本机私有目录的环境中运行全历史扫描和全新安装验证。若托管平台保留旧 PR、缓存对象、Release 附件或构建产物，先删除对应副本；无法自行清理的对象联系平台维护方处理。
5. 当前扫描没有确认真实 API Key 泄露。若后续发现曾经公开的真实凭据，应先在提供方撤销或轮换；删除 Git 文件不会令凭据失效。历史数据库必须按含账号与学生资料的私有数据处理。
6. 协作者重新克隆或按清理结果重建本地引用，避免旧提交重新进入仓库。远端复验通过后，再由维护者决定修改可见性。
