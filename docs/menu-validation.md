## 真实接口结果及限制

OpenRouter 的随机图片与严格 JSON 能力测试通过。初次接口报 `uniqueItems` 不支持，已从发送的 Schema 子集中移除该关键字；本地 Ajv 仍检查唯一性。未部署第二个菜单服务，测试和生产均由 Node 直接发出官网与模型请求。

使用 `openai/gpt-6-luna` 的整图实验中，三篇均在区块或全图复核被阻止发布：出现地点/分类/餐次表述冲突及个别辣椒误读。网站保留旧数据并提供原图、部分候选及诊断；本记录不声称这三篇已成功入库，也不将模型的 `complete` 声明视为准确率保证。

基线候选的局部抽样分别匹配 10/10、9/10、8/10；未匹配包括夜宵水饺遗漏及两个面档辣椒误读。这些数值只描述三十个抽样字段组合，不能推算整个菜单的准确率。追加 `openai/gpt-6.1-sol` 单篇实验通过能力测试，但中途遇到提供商非完整 JSON 响应，没有获得可发布的整篇结果；网站继续按失败处理，未放宽门禁。

格式能力合格的模型可能仍不适合复杂多表菜单。开发者需用选定模型和真实原图核对数据质量，失败时可以换模型、清晰补图或重试。重叠处理和复核减少错误发布，但视觉识别仍有模型误判风险。生产模型 ID 默认空，测试环境凭据没有保存到项目数据库或配置。

可选真实测试 `npm run test:menu:live` 使用 `OPENROUTER_API_KEY`（或开发环境 `OPENROUTER_CODE_API_KEY`）、`MENU_TEST_MODEL` 和开发存档，产生真实模型用量；`MENU_TEST_IDS` 可指定本抽样中的文章。原图、候选、缓存和诊断留在忽略的 `output/playwright/menu-live/`，不作为交付数据提交。
