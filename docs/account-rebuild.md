# 账号与审核重建（2026-10-31）

当前实现说明；完整接口和数据表定义见 [MAP](../MAP.md)。

## 角色与注册

| 身份 | 能力 |
| --- | --- |
| guest | 公开浏览 |
| user | 个人设置、私密收藏、认证申请和工单；不能发表评价或推荐店铺 |
| student | 基础功能、评价、点赞与店铺推荐；公开内容先审后发 |
| admin | 审核、申诉、普通用户/学生管理、工单和内容管理 |
| operator | 管理功能及 admin 账号管理 |

首次及后续注册始终为 user，无邀请码或个人权限授予。admin 不能管理 admin；所有管理者不能管理自己或 operator。管理账号的创建由服务器命令完成，网站无 operator 提权入口。

## 学生身份

新生号/学号为唯一身份标识，先做 NFKC、去首尾空白和大写规范化，姓名和班级供人工核对。待审和被拒申请不占用身份；通过时在写事务中建立唯一学号与唯一账号绑定，同时拒绝竞争申请并通知。数据库唯一约束防止并发重复通过。

本人可确认密码解绑，管理员也可在权限边界内解绑。解绑释放学号，将 student 降为 user、撤回待审内容、使收藏夹私密，并撤销全部会话；再次发布需重新认证。

## 先审后发与通知

展示 ID 与登录用户名独立。展示 ID、头像、昵称、签名、菜品评价、店铺推荐及店铺评价均进入统一审核队列，只有批准才更新公开数据。已发布资料和店铺评价在修改待审期间继续显示旧版；删除店铺评价同时撤回待审修改，防止审核后重新出现。

学生推荐按上海自然日每天最多 10 家；已接收的申请即计次数，拒绝或撤回不返还。申请保留历史、安全摘要、状态、原因与相关入口，用户可撤回自己的 pending 申请。管理员不能审核自己的申请，拒绝必须填写原因，终态不能重复处理。发布、通知及审计记录在事务内完成。

上传图片实际解码、检查尺寸/像素及 2 MiB 大小限制，去元数据后转 PNG。待审字节只存在私有申请载荷；通过后生成 uploads/approved/ 随机文件，终态清理待审图片字节，发布回滚清理文件。

学生认证、审核结果、竞争失败、解绑、角色变更、封禁/解封与工单提交/回复均通知并留记录。封禁申诉需验证账号密码及后端允许申诉开关；正确凭据的封禁登录可查看最近申诉状态和原因。新申诉和工单不接受图片，历史图片只作兼容。

## 密码与会话

**登录不检查或显示密码强度**，只核对凭据，历史弱密码可正常登录。注册和修改新密码要求至少 8 位，包含大小写字母和数字，不允许首尾空白，UTF-8 最多 72 字节；新密码显示逐项检查，旧密码与重复密码不显示强度。服务端执行同一策略，bcrypt cost 为 12。

浏览器使用 HttpOnly、SameSite=Strict Cookie；HTTPS/生产启用 Secure。本地仅保存会话标记。JWT 固定 HS256、签发者和接收者，随机 sid 必须对应数据库有效会话与版本。退出撤销当前会话；改密、封禁、角色变化和解绑撤销全部会话。API 客户端支持 Bearer。

登录、注册、改密、申诉及提交有持久化限流；写请求校验来源。生产应设置准确的 HTTPS APP_ORIGIN 与随机 JWT_SECRET，并使用 HTTPS；开发缺少密钥时在私有目录持久生成随机密钥。

## 迁移与部署

启动基线迁移后执行幂等账号升级：developer → operator，super_admin → admin，旧 student 回到 user 重新认证。删除邀请码、个人权限和旧每周上传表，以及旧菜单凭据配置；旧 student_applications、ban_appeals 表只保留只读历史，不自动导入新审核队列。新队列与会话、绑定、审计、限流、迁移标记共六张表，当前业务表共 29 张。

菜单管理、上传、手动导入及地图写入的网页和 HTTP 入口已移除。菜单自动同步仅使用服务器环境变量，配置见 [菜单运维](menu-sync.md) 与 .env.example。校园地图通过仓库代码维护。

```bash
npm ci
npm run build
npm start
# 构建后，在服务器本地创建 operator；可在裁剪开发依赖后执行
npm run account:operator
```

可用 OPERATOR_USERNAME / OPERATOR_PASSWORD 指定凭据；默认随机生成密码，仅在命令输出显示。已有同名账号不会覆盖。命令先备份现有数据库到 .private/account-backups；测试环境可追加 `-- --reset-test-accounts` 清理测试账号及关联内容，生产禁止此选项。该清理不可用于真实用户库。

本次已按授权执行一次本地测试账号清理并创建 operator，凭据单独交付，不写入文档。保留 5,567 家店铺、966 条菜单供应和 252 个菜品；数据库完整性及外键检查通过。备份位置为 .private/account-backups/data-2026-10-31T12-46-24-604Z.db。本地未配置菜单模型 Key，自动识别需配置后启用。
